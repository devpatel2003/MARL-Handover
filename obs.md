# Observation Spec — `TwoArmHandover` (robosuite)

Generated by running `scratch/explore_env.py`'s env config (`robots=["Sawyer", "Panda"]`,
`env_configuration="opposed"`) and inspecting `env.reset()`'s returned obs dict.

Note: `scratch/explore_env.py` sets `use_object_obs=False`, so the `hammer_*` / `handle_xpos` /
`gripper*_to_handle` / `object-state` keys below will NOT appear when running it as-is —
they're documented here anyway since the handover task needs them. Flip
`use_object_obs=True` to get them.

Task: one robot (robot0, holding the hammer at reset) must pass the hammer to the other robot
(robot1) across the workspace. Per-robot keys are duplicated under both `robot0_*` (Sawyer)
and `robot1_*` (Panda) prefixes.

## Per-robot proprioceptive observations

| Key | Shape | Description |
|---|---|---|
| `robot{i}_joint_pos` | (7,) | Raw joint angles (radians) for the 7 arm joints. |
| `robot{i}_joint_pos_cos` | (7,) | cos(joint_pos) — encodes joint angle without the 2π wraparound discontinuity. |
| `robot{i}_joint_pos_sin` | (7,) | sin(joint_pos) — paired with cos to give a continuous, unambiguous angle representation. |
| `robot{i}_joint_vel` | (7,) | Joint angular velocities (rad/s). |
| `robot{i}_joint_acc` | (7,) | Joint angular accelerations (rad/s^2). |
| `robot{i}_eef_pos` | (3,) | End-effector (gripper) position in world frame: (x, y, z). |
| `robot{i}_eef_quat` | (4,) | End-effector orientation as a quaternion (x, y, z, w), computed from the arm's eef body. |
| `robot{i}_eef_quat_site` | (4,) | End-effector orientation quaternion computed from the eef *site* instead of the body — should closely match `eef_quat`; kept separate because site and body frames can differ slightly depending on robot model. float32 (rest are float64). |
| `robot{i}_gripper_qpos` | (2,) | Gripper finger joint positions (how open/closed the gripper is). |
| `robot{i}_gripper_qvel` | (2,) | Gripper finger joint velocities. |
| `robot{i}_proprio-state` | (50,) | Concatenation of all `robot{i}_*` keys above (7+7+7+7+7+3+4+4+2+2 = 50). This is the flat vector actually fed to the policy network; the individual keys exist for readability/debugging. |

`i` is `0` for the first robot in the `robots=[...]` list (Sawyer) and `1` for the second (Panda).

## Object / task-relevant observations (needs `use_object_obs=True`)

| Key | Shape | Description |
|---|---|---|
| `hammer_pos` | (3,) | World position of the hammer (the object being handed over). |
| `hammer_quat` | (4,) | Orientation of the hammer as a quaternion. |
| `handle_xpos` | (3,) | World position of the hammer's handle (the graspable part) — single handle, unlike the two-handle pot in `TwoArmLift`. |
| `gripper0_to_handle` | (3,) | Vector offset from robot0's gripper to the handle. Reaching/grasping shaping signal for whichever robot currently needs to grab or receive the hammer. |
| `gripper1_to_handle` | (3,) | Same as above but for robot1. |
| `object-state` | (16,) | Concatenation of all object-relevant keys above (3+4+3+3+3 = 16). Flat vector fed to the policy for object/task state, analogous to `proprio-state` for robots. |

## Notes for the latent-comm experiment

- `robot0_proprio-state` and `robot1_proprio-state` are the natural per-agent local observations
  (50-dim each) — each arm only "sees" its own joints/eef/gripper in the no-comm baseline.
- `object-state` (16-dim) is shared/global task info (hammer + handle position) — decide whether
  this is visible to both agents in all conditions, or withheld to force reliance on the
  learned latent channel. Since only one gripper is holding the hammer at a time, this is the
  key signal for "who has it" / "where should the receiving arm move to."
- The learned latent variable would sit alongside (or replace parts of) `object-state` /
  the other agent's `proprio-state` as an additional input each agent receives, depending on
  the condition (`cond0`/`cond1`/`cond2`).
